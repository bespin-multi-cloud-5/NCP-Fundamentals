# 07 Cloud DB for MySQL / 01 NCP Database 서비스 개요

앞 챕터에서 파일을 서버 밖으로 이전했고 서버에 남아 있는 것은 데이터다. 관리형 데이터베이스가 무엇을 담당하고 무엇을 남기는지, NCP가 어떤 서비스로 나누어 제공하는지 다룬다.

## What you will learn

- 플랫폼이 담당하는 범위 — 설치와 초기 설정, 버전 업그레이드, 백업, 장애 감지와 복구, 이중화, 지표 수집
- 사용자에게 남는 범위 — 스키마 설계와 쿼리, 접근 통제 설정, 용량과 성능 등급 선택. 관리형이 대신 수행하는 것은 운영이지 설계가 아니다
- OS에 접속할 수 없다는 점 — 로그 파일을 열어 확인하던 방법이 통하지 않으므로 콘솔이 표시하는 상태와 클라이언트 접속 결과가 판단 근거가 된다
- NCP는 엔진마다 서비스가 별도로 존재한다는 점 — `Cloud DB for Cache`만 엔진명이 아니라 용도를 이름에 두고, 엔진을 변경하는 것이 서비스를 변경하는 것과 같아진다
- `고가용성 지원`을 사용하면 Master와 Standby Master 둘이 되고 Multi Zone은 그 하위 선택이라는 점 — 사용하지 않으면 `Stand Alone`이고 자동 복구가 없다
- 읽기 부하를 `Slave Server`로 분산하고 Load Balancer와 연동한다는 점 — 앞 챕터에서 생성한 자원이 데이터베이스 앞에도 배치된다
- 접속 포트를 `3306` 또는 `10000`~`20000` 사이에서 지정한다는 점 — 기본 포트는 사용할 수 있으나 그 밖의 값은 범위 안으로 제한되므로 임의의 포트를 고르는 구성은 성립하지 않는다
