# 06 Object Storage / 02 Bucket 생성 및 객체 관리

Bucket을 생성할 때 무엇을 지정하는지, 객체에 무엇이 부여되는지 다룬다. 파일 하나를 업로드하여 공개하지 않은 주소와 공개한 주소가 어떻게 다른지 확인한다.

## What you will learn

- 버킷 이름만 생성한 뒤 변경할 수 없고 나머지 항목은 대부분 변경 가능하다는 점 — 이름이 주소의 일부이기 때문이다
- 버킷의 `공개` 설정이 목록의 공개 여부라는 점 — 파일 하나를 조회할 수 있는지는 그 파일의 권한이 결정하므로, 목록은 비공개로 두고 필요한 파일만 공개하는 구성이 통상적이다
- 객체 잠금(WORM)이 지정한 기간 동안 변경과 삭제를 차단한다는 점, 그리고 콘솔에서 바로 활성화되지 않고 고객센터에 신청해야 한다는 점
- 암호화가 저장될 때 적용되므로 읽고 쓰는 방법이 달라지지 않는다는 점 — 키는 NCP 관리형 키 하나만 선택할 수 있다
- 시스템 메타데이터와 사용자 정의 메타데이터의 구분 — 직접 지정할 수 있는 것은 `Content-Type`과 `x-amz-meta-` 접두 둘뿐이고, `x-amz-storage-class`처럼 플랫폼이 부여하는 값이 S3 호환의 흔적으로 남아 있다
- `Link`가 공개하지 않아도 값을 갖는다는 점 — 주소는 이름으로 이미 정해져 있으며, 주소가 있다는 것과 조회할 수 있다는 것은 다르다
- 계층마다 삭제 정책이 반대라는 점 — 버킷은 객체가 남아도 함께 삭제되지만, 서비스 이용 해지는 버킷이 남으면 차단된다

## Examples

- `lab15` → 이용 신청, Bucket 생성, 업로드, 공개 전후의 주소 비교, 폴더와 계층, 다운로드와 삭제
- 공개하지 않은 객체의 주소로 접근하여 `AccessDenied` XML을 확인하고, 공개로 변경한 뒤 같은 주소가 열리는 것을 대조한다
- 디렉터리를 그대로 업로드하면 계층이 사라지는 것을 직접 확인한다
- 버킷을 삭제할 때 이름을 직접 입력하게 하는 확인 절차와, 버킷이 남아 있으면 이용 해지가 차단되는 문구를 확인한다
